# 🤖 Telegram Media Sync Engine

Автоматизована система синхронізації та публікації медіафайлів (фото, відео, анімацій) з хмарного сховища **Google Drive** у канали та чати **Telegram** за допомогою **GitHub Actions**.

📑 1. Логіка Роботи Реєстру та Синхронізації (sync_script.py)
Цей скрипт відповідає за підтримку бази даних в актуальному стані. Він виконує абсолютну дельта-синхронізацію між фізичними папками на Диску та рядками в Таблиці.

⚙️ Службовий аркуш: ⚙️ Налаштування Папок
Роль: Інтерактивний інструмент аудиту та панель керування для режисера контенту.

Автоматичне виявлення: Скрипт сканує кореневу папку на Диску. Якщо з'являється нова підпапка, вона додається в службовий аркуш із прапорцем НІ та статусом ✨ Нова папка! Очікує вашого правила. Це безпечний режим (контент не потрапить в ефір без вашого дозволу).

Контроль цілісності: * Якщо ви перейменували папку на Диску, скрипт оновить її назву в службовому аркуші.

Якщо папка була видалена з Диску, скрипт зафіксує маркер ❌ ВИДАЛЕНО НА ДИСКУ (Перевірте чи діє правило!).

📅 Тематичний контентний аркуш: П'ятниця
Абсолютний збір даних: Скрипт зчитує файли з усіх підпапок, незалежно від їхнього поточного статусу активності.

Додавання нових файлів: Нові медіафайли записуються в кінець аркуша із початковими лічильниками публікацій 0 (для Постів) та 0 (для Сторіс).

Видалення застарілих даних: Якщо ви видалили файл із Google Диску, скрипт автоматично видалить відповідний рядок із таблиці контенту, зміщуючи інші рядки вгору для запобігання «діркам» у базі.

🚀 2. Інтелектуальна Логіка Публікатора (publish_content.py)
Публікатор запускається з двома параметрами: mode (режим: post/story) та tab_name (назва аркуша: "П'ятниця").

🔍 Крок 2.1: Алгоритм Ротації та Пріоритетності (План Публікації)
Для вибору ідеального файлу на поточний момент скрипт використовує багаторівневу фільтрацію:

Пул мінімальної ротації (Min-pool): Скрипт аналізує потрібну колонку лічильника (Колонка D для постів, E для сторіс) і вибирає файли, які мають найменшу кількість публікацій у базі. Це гарантує рівномірний розподіл контенту.

Аналіз календаря та свят (get_active_rules_ordered): Скрипт формує динамічний список активних категорій на основі поточної дати:

Сезонні/Святкові правила: Якщо поточна дата потрапляє в діапазон (наприклад, 22.12 - 31.12 для Нового Року, або 23.11 - 30.11 для Чорної П'ятниці), ця категорія стає найвищим пріоритетом.

День тижня: Наступним пріоритетом додається поточний день тижня (наприклад, "П'ятниця").

Глобальний fallback: Наприкінці списку завжди стоїть категорія "Різне".

Фінальний вибір: Скрипт проходить за списком активних категорій і шукає перший файл із пулу Min-pool, який належить до цієї категорії. Якщо збігів за правилами не знайдено, скрипт бере перший-ліпший файл із мінімальною ротацією, щоб сторінка ніколи не залишалася порожньою (захист від «повного штилю»).

🛠️ Крок 2.2: Нормалізація та Конвертація Медіа (FFmpeg / Pillow)
Система підтримує суворе розділення форматів контенту:

Документи (PDF, DOC, DJVU тощо): Автоматично ігноруються, а на службовий аркуш виводиться системне попередження про помилку формату контенту.

Анімації (.gif): Скрипт за допомогою утиліти FFmpeg конвертує GIF у потокове відео .mp4 (кодек yuv420p, сумісний із Meta API), оскільки Instagram не підтримує нативні GIF.

Apple формати (.heic, .heif): За допомогою бібліотеки pillow-heif скрипт «на льоту» перекодовує зображення у стандартний .jpg високої якості (90%).

👁️ Крок 2.3: Візуальний Аналіз через Очі ШІ (Gemini 1.5 Flash)
Якщо публікується Пост, системі потрібен унікальний та влучний опис.

Для відео: Скрипт за допомогою FFmpeg відкушує перший кадр (00:00:01) як зображення.

Генерація опису: Скрипт відправляє фінальне зображення або кадр через Multimodal API до моделі Gemini 1.5 Flash. ШІ виступає в ролі професійного розважального маркетолога: він дивиться на реальний вміст картинки, враховує контекст поточної категорії і генерує один короткий, смішний, життєвий коментар українською мовою з відповідними емодзі.

🌐 Крок 2.4: Публікація через Хмару та Оновлення Бази
Файл завантажується у тимчасову публічну папку на Google Диску (TEMP_PUBLIC_FOLDER_ID), щоб Meta-платформи могли отримати прямий лінк для завантаження медіа.

Викликається Meta Graph API:

Контент публікується в Instagram (як Сторіс або Пост згенерований ШІ).

Якщо це режим post, скрипт автоматично робить кроспостинг на сторінку Facebook (дублює фото/відео та текст).

Після успішного підтвердження від серверів Meta:

На відповідному контентному аркуші лічильник публікацій файлу збільшується на +1.

Тимчасовий файл на Google Диску та локальні медіафайли повністю видаляються для дотримання чистоти системи.

⏰ 3. Автоматизація та Розклад (GitHub Actions Workflow)
Вся система працює повністю автономно на серверах GitHub і не потребує увімкненого комп'ютера чи сторонніх серверів.

📅 Розклад запуску (Синхронізація з часом у Німеччині)
Запуски відбуваються за допомогою cron-розкладу, налаштованого з урахуванням UTC-зміщення для Центральної Європи (Берлін/Штутгарт):

07:00 UTC (09:00 за Берліном): Ранковий запуск. Код визначає годину, вмикає режим STORY та публікує сторіс для ранкового охоплення.

11:00 UTC (13:00 за Берліном): Обідній запуск. Година не входить у блок сторіс, тому скрипт автоматично перемикається в режим POST: запускається візуальний аналіз ШІ, створюється текст і пост виходить в Instagram та Facebook.

18:00 UTC (20:00 за Берліном): Вечірній запуск. Година відповідає вечірньому блоку, система публікує другу вечірню STORY.

🛡️ Системна стабільність в Actions
Перед кожним запуском віртуальна машина автоматично розгортає оточення:

Завантажує актуальну версію коду.

Встановлює системний пакет ffmpeg для обробки відео/кадрів.

Розгортає Python та інсталює залежності (requests, google-api-python-client, pillow-heif тощо).

Безпечно витягує зашифровані ключі доступу (secrets) для Google Cloud, Meta API та Gemini AI.

🛠️ Технічні зауваження для Адміністратора
Перейменування категорій: Якщо ви перейменували підпапку на Диску, синхронізатор оновить її у службовому аркуші. Проте, файли, які вже були внесені в аркуш П'ятниця раніше, залишаться зі старою назвою категорії. Рекомендується зробити швидку масову заміну назви через Ctrl + H безпосередньо в таблиці П'ятниця.

Людський фактор: Завдяки вбудованому захисту (.strip().upper()), ручне введення статусів ТАК чи НІ на службовому аркуші захищене від випадкових пробілів чи регістру літер.

Формати медіа: Скрипт суворо валідує розширення файлів. Використовуйте лише стандартні формати зображень та відео (JPG, PNG, HEIC, MP4, GIF). Документи система відфільтрує самостійно та залишить лог-попередження у стовпчику E службової таблиці.
